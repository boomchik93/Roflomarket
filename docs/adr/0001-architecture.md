# ADR 0001. Архитектура и процесс

Дата: 2026-09-30. Статус: принято, кроме пунктов в разделе «Не подтверждено».

## Контекст

Командный проект курса «Разработка JS»: 5 человек, сдача в декабре 2026. Курс требует JavaScript во фронтенде и бэкенде и Postgres. Двое из команды пишут на Go. Цель команды — отказоустойчивый сервис. Все участники работают через Claude Code.

## Решения

### Два бэкенд-сервиса

- `apps/gateway` на Node.js: auth, REST и WebSocket для клиента, профили, CRUD рынков, комментарии. Закрывает требование курса о JavaScript на бэкенде и содержит существенную логику, а не только проксирование.
- `services/engine` на Go: ledger, AMM, сделки, расчёт рынков.

Причина: ошибки в деньгах самые дорогие, поэтому эта часть изолирована в одном сервисе с одним владельцем данных.

Цена: два набора инструментов, две CI-ветки, engine зависит от двух человек.

### Один Postgres, две схемы

Схемы `gateway` и `engine`. Сервис работает только со своей схемой. Чужие данные получает через RPC. В таблицы денег пишет только engine.

### Контракт первым

Gateway и engine общаются по Connect RPC. Контракт описан в protobuf в `packages/contracts`, код для TypeScript и Go генерирует `buf`. CI запрещает несовместимые изменения через `buf breaking`.

Причина: согласованный контракт позволяет писать два сервиса параллельно.

### Рынок

Только игровая валюта. Автоматический маркет-мейкер с постоянным произведением, целочисленная арифметика. Подробности — в `docs/spec.md`.

Книга заявок отклонена: заметно сложнее и не нужна при малом числе участников.

### Отказоустойчивость

- Сделка в одной транзакции с блокировкой строки рынка.
- Ledger с двойной записью.
- Idempotency key на меняющих операциях.
- События через outbox.
- Сервисы stateless, по две реплики за Caddy.
- Миграции совместимы с предыдущей версией кода.

Ограничение: один VPS. Отказ машины останавливает сервис. Защита данных — регулярный `pg_dump` во внешнее хранилище.

### Выкладка

Docker Compose на одном VPS. Docker Swarm и Kubernetes отклонены как лишние для срока проекта. Отдельного staging нет.

Следствие: `docker compose up` пересоздаёт контейнеры без гарантии нулевого простоя. Короткий разрыв сглаживают две реплики и повторные попытки на стороне Caddy.

### CI/CD и changelog

- GitHub Actions. Проверки запускаются только для затронутых сервисов.
- Conventional Commits, squash merge, проверка заголовка PR.
- `release-please` ведёт `CHANGELOG.md` и версию. Merge release-PR создаёт тег, собирает образы в GHCR и выкладывает их на VPS.
- Одна версия на весь репозиторий.

### Работа с Claude Code

- MCP-серверы: Figma, Context7, Playwright. Конфигурация в `.mcp.json`.
- Корневой `CLAUDE.md` и по одному в каждом сервисе.
- Три агента: `reviewer`, `test-writer`, `figma-implementer`.
- Hook после правки файла запускает форматирование и линтер.
- Подпись Claude в коммитах и PR отключена в `.claude/settings.json`.

## Не подтверждено

- Преподаватель не подтвердил письменно, что сервис на Go допустим. Если нет, engine переписывается на TypeScript с теми же правилами.
- TypeScript вместо чистого JavaScript. Критерии курса про это молчат.
- Конкретные библиотеки: Fastify, Drizzle, pgx. Можно заменить до появления кода.
