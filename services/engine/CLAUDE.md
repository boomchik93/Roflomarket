# engine

Ядро рынка. Go, pgx, схема Postgres `engine`. Единственный сервис, который меняет балансы.

Отвечает за: ledger, AMM, исполнение сделок, позиции, расчёт рынков, события об изменении цен.

Правила рынка и формулы — в `docs/spec.md`. При расхождении кода и спецификации права спецификация: сообщи о расхождении, не подгоняй молча.

## Правила

- Сделка — одна транзакция Postgres. Строку рынка блокируй через `SELECT ... FOR UPDATE` до расчёта цены.
- Ledger с двойной записью. Баланс не хранится отдельным изменяемым числом без проводок. Сумма всех проводок равна нулю.
- Каждая меняющая операция принимает idempotency key. Повтор с тем же ключом возвращает первый результат и ничего не списывает.
- Суммы, цены, доли — `int64` в минимальных единицах. `float64` в расчётах денег запрещён.
- Событие для gateway пиши в таблицу outbox в той же транзакции, что и сделку. Отправка события отдельно от транзакции теряет его при падении.
- Сервис stateless. Обязательный endpoint `GET /healthz`. По SIGTERM заверши текущие запросы.
- Ошибки оборачивай с контекстом: `fmt.Errorf("execute trade: %w", err)`. `panic` только при невозможности старта.
- Миграции обратно совместимые. Используй skill `add-migration`.

## Тесты

- Математика AMM покрыта property-тестами: инварианты из `docs/spec.md` проверяются на случайных входах.
- Логика с транзакциями проверяется интеграционными тестами на реальном Postgres, включая параллельные сделки на одном рынке.

## Команды

Из `services/engine`:

```bash
go build ./...
go vet ./...
go test -race ./...
```

Интеграционным тестам нужен Postgres: `docker compose -f infra/docker-compose.yml up -d` из корня.
