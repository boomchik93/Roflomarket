# Изменение контракта

Контракт меняется первым, код сервисов — после. Так два человека могут параллельно писать gateway и engine под один согласованный интерфейс.

1. Опиши изменение в `.proto` в `packages/contracts`.
   - Только обратно совместимо: новые поля, новые RPC, новые значения enum.
   - Номер и тип существующего поля не меняй. Удаляемое поле помечай `reserved`.
   - Деньги — `int64` в минимальных единицах.
   - Меняющий RPC содержит `idempotency_key`.
2. Проверь из `packages/contracts`:
   ```bash
   buf lint
   buf breaking --against '../../.git#branch=main,subdir=packages/contracts'
   ```
   Если `buf breaking` падает, изменение несовместимо. Переделай его как добавление. Не отключай проверку.
3. Сгенерируй код: `buf generate`. Сгенерированные файлы не правь руками.
4. Закоммить `.proto` и сгенерированный код одним коммитом.
5. Если задача затрагивает оба сервиса, открой PR с контрактом отдельно и раньше, чем PR с реализацией. После merge контракта владельцы сервисов работают независимо.
6. Реализацию делай в таком порядке: сначала engine (сервер), потом gateway (клиент). Клиент не должен вызывать RPC, которого нет в выложенной версии сервера.

Если несовместимое изменение действительно нужно, остановись и спроси человека. Это решение команды, не агента.
